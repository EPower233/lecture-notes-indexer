## 一、需求与硬约束（用户初始规格）

把本地 Obsidian 讲义库里的 **CMU 15-445（数据库系统）** 与 **Mathematics（概率论与数理统计）** 双语讲义建成可检索库（公开展示与仓库快照仅含这两类课程，个人笔记不纳入）：

1. 用 seekdb 官方语法建 `vault` 库：`notes / chunks(VECTOR(512)+全文索引) / glossary / links`。
2. `ingest.py`：解析 课程/讲次/双语标题 → 按 `##/###` 切块并保留 `heading_path` → 抽取就近的「📍 PPT 第 N 页」页码 → 从「## 术语速查表」抽术语 → 抽内部链接并标 `valid` → bge-small-zh-v1.5 生成向量 → 批量入库 → 打印统计。
3. 给出从零复现命令，每步配可运行校验与预期输出。

**三条红线（用户明确）**：
- ❌ 不写前端（第一阶段只做数据层）——后续阶段才逐步加检索服务与 Web。
- ❌ **不把向量检索与全文检索留到客户端拼接**——混合必须在 seekdb **单条 SQL** 内完成。
- ❌ **不修改数据源目录任何文件**——本地 Obsidian 讲义库全程只读。

## 二、开发历程（按阶段）

### 阶段 1 · 数据层设计与建表（schema.sql，63 行）
- 用 seekdb 官方向量 + 全文语法建 4 张表；`chunks` 关键点：
  - `emb VECTOR(512)`；
  - `FULLTEXT KEY ft_chunks_content (content) WITH PARSER ik PARSER_PROPERTIES=(ik_mode="smart")`；
  - `VECTOR KEY vidx_chunks_emb (emb) WITH (DISTANCE=L2, TYPE=HNSW, LIB=VSAG, M=16, EF_CONSTRUCTION=200, EF_SEARCH=64)`；
  - `ORGANIZATION = HEAP`。
- `note_id / chunk_id` 用**显式 BIGINT 主键**（非自增），便于入库幂等重建与前端稳定引用。
- **踩坑**：用 Python 逐句执行 `schema.sql` 时，最初按「行」过滤 `--` 注释，结果把第一条 `CREATE DATABASE` 整句误删。**修正**：先整体去掉注释行，再按 `;` 切分执行。

### 阶段 2 · 在 Windows 部署 seekdb（改用上游镜像 + Docker Desktop）
- 用户纠正：**不要**用 WSL 里那个开发测试实例（:12881），要从上游拉干净镜像在本机部署。经 AskUserQuestion 确认用 **Docker Desktop**。
- **踩坑（端口）**：宿主 2881/2886 无法绑定——落在 Windows Hyper-V 保留端口段 2791–2890 内（`netsh interface ipv4 show excludedportrange protocol=tcp` 证实）。**修正**：宿主端口改 **20881** → 容器 2881。
- **踩坑（pylib）**：`pylib_seekdb` 无 Windows wheel（仅 macOS/Linux cp311/312），排除嵌入式方案，坚定走「Docker 容器 + MySQL 协议（pymysql）」路线。
- **踩坑（Docker CLI）**：Git Bash 里 `docker-credential-desktop` 不在 PATH。**修正**：`export PATH="$PATH:/c/Program Files/Docker/Docker/resources/bin"`。
- 容器：`oceanbase/seekdb:latest`，版本 `5.7.25-OceanBase seekdb-v1.4.0.0`。

### 阶段 3 · 入库管道（ingest.py，441 行）
- 扫描：`rglob('*.md')`，跳过隐藏目录；**只读**打开，绝不写数据源。
- 元数据解析：目录名 `L{N} {Agent} {中文题} {English Title}`、文件名 `(\d{2}-\d{3})-lecture-(\d+)(?:-(slug))?`；`zh_title` 取 agent 词后的中文串，`en_title` 由 slug 还原。
- 切块：按 `##/###` 分段并累积 `heading_path`；「## 术语速查表」段**排除**出 chunk（单独进 glossary）；超长段（>800 字）按 100 字重叠再切，标 `(part N)`。
- 页码：正则匹配 `📍 *PPT 第 4–5 页*`（兼容范围/顿号/逗号枚举），取 min/max → `page_start/page_end`，跨段**就近继承**。
- 链接：仅抽跨文件 `.md` 链接，URL 解码后相对笔记目录解析；`valid = 目标文件存在 且 锚点在目标锚点集合内`（锚点集 = 标题 slug + 术语）。
- 向量：`BAAI/bge-small-zh-v1.5`（512 维，CPU，归一化），**passage 侧原文**、**query 侧加检索指令前缀**；带 `emb_cache_{md5}.npy` 缓存避免重复编码。
- 入库：`DELETE` 后 `INSERT` 幂等重建；末尾打印统计。
- **踩坑（编码）**：Windows GBK 控制台打印 emoji/中文 `UnicodeEncodeError`。**修正**：模块顶部 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')`；且**只在 ingest.py 包一次**——被别的脚本 import 时若重复包裹会触发 “I/O operation on closed file”（GC 关闭共享 buffer）。
- **用户反馈修正（页码格式）**：用户说标记像「📍 27」，实际数据是「📍 *PPT 第 4–5 页*」；正则据此覆盖范围/枚举。

### 阶段 4 · 检索核心（search.py，245 行）——单 SQL 混合
- `Searcher.search(query, mode∈{hybrid,vector,fts}, k, alpha, course, kind, lecture_no, keywords)`。
- **hybrid 单条 SQL**：`score = (1-α)·rel/(1+rel) + α·1/(1+dist)`，其中 `rel=MATCH(content) AGAINST(%s)`、`dist=l2_distance(emb,%s)`；结构化过滤 `WHERE` 下推同一条 SQL。**红线达成：库内融合、非客户端拼接。**
- **踩坑（占位符顺序）**：pymysql 按 `%s` 在 **SQL 文本**中出现顺序绑定，而 `WHERE` 在 `SELECT` 之后；最初 `params + [vec,kw,...]` 把过滤参数放前面导致错位。**修正**：`[vec, kw, alpha, kw, kw, alpha, vec] + fparams + [k]`；并修正 α 语义（α=向量权重，出现两处）。
- **踩坑（中文全文召回）**：BOOLEAN MODE 下「版本链」等 ik 未单独收录的复合词**召回为 0**。**修正**：fts/hybrid 改**自然语言模式** `AGAINST(%s)`，由 ik 对查询侧自动分词，召回正常（「版本链」→ L20 MVCC，rel≈14.97）。
- CLI：`search.py "查询" --mode/--k/--alpha/--course/--kind/--lecture/--keywords/--term/--note`。

### 阶段 5 · HTTP 服务（serve.py，211 行）
- FastAPI + lifespan 预热模型（`s.model` + `embed_query("warmup")`），CORS 全开；env 配置 seekdb 连接与 `VAULT_DIR`。
- 接口：`/health`、`/api/search`、`/api/term`、`/api/note`(id/path)、`/api/note/{id}/chunks|glossary|links`、`/api/notes`、`/api/chunk/{id}`、`/api/courses`、`/api/stats`、`/api/vault-file`（只读取图，防目录穿越）、`/`→`/ui/`、`StaticFiles` 挂 `/ui`。
- **踩坑（并发 500）**：单个共享 pymysql 连接被 FastAPI 线程池多线程并发使用，`/api/stats` 偶发 500。**修正**：`threading.local()` 每线程一条连接（`conn` 属性惰性建连并检 `open`）。12 路并发压测后全 200。
- **安全**：`/api/vault-file` 用 `resolve()` + `is_relative_to(VAULT_DIR)` 拦截穿越，实测 `../../../../Windows/win.ini` → 404。

### 阶段 6 · Web 前端（用户追加「构建检索页面 + 笔记浏览」）
- `web/index.html`（189 行）：检索页——查询框、mode 切换、course/kind/讲次/α 滑块/k/关键词覆盖、术语速查、结果卡片（score·d·rel + 课程/讲次/页码徽章 + heading_path + 高亮摘要 + 整卡链接）、右侧按课程分组浏览。

**EXPLAIN 层面的认知（本次实测补充）**：
- `WHERE MATCH...AGAINST` → 走 `TEXT RETRIEVAL SCAN(ft_chunks_content)`，**ik 全文索引被优化器实际选用**；
- `ORDER BY l2_distance(...) LIMIT` → `TOP-N SORT` + `TABLE FULL SCAN`（**精确**，万行级数据下快且准）；
- 加 `APPROXIMATE` → `VECTOR INDEX SCAN(vidx_chunks_emb)`，估算 9µs（**HNSW 近似**，≈150×）；
- hybrid 单条 SQL → `MERGE JOIN` + 融合打分 `TOP-N SORT`，`sort_keys` 同含 `MATCH` 与 `l2_distance`，**证明融合在库内一次完成**。

## 四、运行期事故与韧性加固（2026-10-28）

打包验证样例期间，seekdb 容器**两次异常退出**（`Exited (255)`），随后 **Docker Desktop 引擎整体停止**（命名管道 `dockerDesktopLinuxEngine` 消失，`docker-desktop` WSL 发行版 `Stopped`）。

- **定位**：容器日志停在「observer process wait begin」后无错误栈、无 OOMKilled 标记、`docker events` 无 die/kill 记录，宿主未重启、Docker Desktop 后端进程时间早于容器——判定为**外部环境因素**（很可能笔记本休眠/恢复导致 WSL2 VM 挂起-恢复，容器被外部信号终止），非本项目代码缺陷。
- **恢复**：`docker start seekdb`（重启**同一**停止容器，**不** `rm`/重建，数据完整保留）→ 6s 后引擎就绪、SQL 可读；实测各表行数与崩溃前逐项核对一致；`search.py` 三模式复测 hybrid `score=0.7681` 与既往一致。Docker Desktop 由 `Start-Process` 重新拉起。
- **加固**：`docker update --restart unless-stopped seekdb`——此后 Docker/机器恢复即自动拉起容器（本次引擎恢复后 `Running=1` 即自动生效）。
- **对检索服务的影响**：uvicorn 线程池里缓存的旧连接指向已死容器 → `/health` 一度 500。**处置**：重启 uvicorn（新进程重新建连 + 预热模型），随后 `/health` 3s 内恢复 `{"status":"ok"}`。
- **交付建议**：演示前确认 `docker ps` 中 seekdb 为 `Up`；若刚休眠恢复，等待容器自愈或手动 `docker start seekdb`，并在服务层对首请求失败做一次重连（现有 `conn` 属性已在 `not c.open` 时重连）。
